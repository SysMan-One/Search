# SEARCH -- выдача записей, содержащих заданные строки

Выдаёт записи набора файлов, удовлетворяющие логической комбинации
заданных строк поиска.

Формат:

```
SEARCH спецификация-файла[,...] строка-поиска[,...] [/квалификаторы]
```

Строка поиска -- это обычная подстрока: ни шаблонов, ни регулярных
выражений, ничего не нужно экранировать. Спецификация файла, наоборот,
раскрывается самой утилитой, поэтому её следует закавычить от
командного интерпретатора:

```
$ search '*.c' STS$K_
```

Первое слово, не являющееся квалификатором, -- это список
спецификаций файлов; каждое следующее слово -- список строк поиска.
Элементы списка разделяются запятыми; элемент, содержащий запятую,
берётся в двойные кавычки либо передаётся отдельным словом:

```
$ search '*.c' alpha,beta        две строки
$ search '*.c' '"alpha,beta"'    одна строка
$ search '*.c' alpha beta        две строки
```

Квалификатор допускает однозначное сокращение и может записываться
в длинной форме Unix: --EXACT вместо /EXACT. Одиночный дефис
начинает обычное значение, так что файл с именем -notes.txt
запрашивается как есть; -h -- краткий синоним /HELP.

Слово, начинающееся с косой черты, считается квалификатором только
если оно называет квалификатор: /RECURSIVE называет, /usr/src/*.c --
нет, поскольку в этой системе с косой черты начинается и абсолютная
спецификация файла. Слово, не назвавшее квалификатора, --
это параметр: первое такое слово задаёт список спецификаций файлов,
каждое следующее -- список строк поиска. Опечатка в квалификаторе
поэтому становится параметром, а не отвергается; чтобы опечатку
называли опечаткой, пишите квалификатор в длинной форме, --NAME:
она ничем другим быть не может.

Одиночное \`--\` завершает квалификаторы, так что до файла или строки,
названных как квалификатор, всё же можно добраться:

```
$ search -- notes.txt /EXACT
```

Образ завершается с кодами grep: 0, если совпала хотя бы одна запись,
1, если не совпало ничего, 2, если было сообщение об ошибке -- файл не
открылся или не прочёлся, команду нельзя выполнить, -- что бы ещё ни
совпало. Запуск проверяется так же, как у grep.

## ПАРАМЕТРЫ

### спецификация-файла

Файлы, подлежащие просмотру, через запятую. Шаблоны раскрывает сама
утилита -- см. тему ШАБЛОНЫ.

Спецификация без шаблона понимается буквально: каталог означает всё
его содержимое, файл означает сам себя.

Абсолютная спецификация пишется как есть -- /usr/src/*.c, /etc,
/*.c с /RECURSIVE -- и за квалификатор не принимается; о том, как
они различаются, см. описание команды.

### строка-поиска

Искомые строки, через запятую. Строка сопоставляется как подстрока,
в любой позиции записи.

Если не задан /EXACT, регистр букв не учитывается -- в любой
письменности, которую знает локаль: "поиск" находит Поиск и ПОИСК так
же, как "alpha" находит Alpha. Текст считается UTF-8; локаль берётся
пользовательская, если она UTF-8, иначе C.UTF-8.

Способ объединения нескольких строк задаёт /MATCH.

## /EXACT -- учитывать регистр

Сравнивает буквы как есть, так что ALPHA, Alpha и alpha -- три
разные строки.

По умолчанию регистр букв не учитывается -- латинских, кириллических
и любых других, которые знает локаль.

## /MATCH -- объединение нескольких строк поиска

```
/MATCH=вариант
```

Задаёт, что считать совпадением записи, когда строк поиска задано
больше одной:

```
OR      присутствует хотя бы одна строка   (по умолчанию)
AND     присутствуют все строки
NAND    хотя бы одна строка отсутствует
NOR     не присутствует ни одна строка
```

Вариант допускает однозначное сокращение: /MATCH=A -- это AND,
а /MATCH=N -- ни то ни другое.

/MATCH=NOR с единственной строкой выдаёт записи, которые её не
содержат, -- это способ получить "всё, кроме".

## /WINDOW -- выдача записей вокруг совпадения

```
/WINDOW[=(n,m)]
```

Выдаёт n записей перед каждой совпавшей и m записей после неё. Одно
значение означает столько же с обеих сторон, отсутствие значения --
по одной с каждой стороны.

Два совпадения, окна которых перекрываются, дают один непрерывный
участок записей -- ни одна запись не выдаётся дважды, -- а разрыв
между участками отмечается пустой строкой.

Круглые скобки являются метасимволами интерпретатора, поэтому их
следует закавычить:

```
$ search '*.c' TODO "/WINDOW=(1,2)"
```

## /PAGE -- остановка в конце страницы

Квалификатор отрицаемый: /PAGE останавливает выдачу в конце каждой
страницы и ждёт, /NOPAGE выдаёт всё подряд.

На запрос пустая строка выдаёт следующую страницу; ответ,
начинающийся с Q, а также конец файла с терминала прекращают выдачу
вовсе -- оставшиеся файлы даже не открываются.

Постраничный режим предоставляется только тогда, когда вывод
действительно является терминалом и ответ есть откуда прочитать,
так что перенаправленный запуск не ждёт нажатия клавиши, в какой бы
форме квалификатор ни был задан. Высота страницы -- та, о которой
сообщает драйвер терминала; запись шире экрана считается за столько
строк, на сколько она переносится.

Ответ читается со стандартного ввода, если это терминал, и из
/dev/tty в противном случае, поэтому выдачу можно листать и тогда,
когда она передана по каналу другой утилите.

По умолчанию постраничный режим выключен.

## /HIGHLIGHT -- подсветка найденного

```
/HIGHLIGHT[=стиль]
```

Выделяет в каждой выданной записи участки, принадлежащие строкам
поиска. Стиль -- один из:

```
BOLD        по умолчанию
REVERSE
UNDERLINE
RED
GREEN
YELLOW
```

Два перекрывающихся вхождения -- ALPHA и PHA внутри ALPHABET --
выделяются как один участок, а не как два вложенных. Запись,
выданная в составе окна /WINDOW, собственного совпадения не
содержит и не подсвечивается.

Выделение выполняется escape-последовательностями ECMA-48, которым
место на экране, а не в файле, поэтому по умолчанию оно
предоставляется только тогда, когда вывод является терминалом.
Явно заданный /HIGHLIGHT отменяет это правило -- обычная причина
передача по каналу листалке, понимающей эти последовательности, --
а /NOHIGHLIGHT отключает подсветку при любом выводе.

Последовательности не занимают ни одной позиции экрана и не
учитываются пейджером /PAGE.

## /NUMBERS -- выдавать номер записи

Квалификатор отрицаемый: /NUMBERS предваряет каждую выданную запись
её номером, /NONUMBERS отменяет это.

Записи нумеруются от единицы внутри каждого файла независимо от
того, выдаются они или нет, так что номер -- это номер строки в
файле.

По умолчанию нумерация выключена.

## /HEADING -- объявлять имя файла

Квалификатор отрицаемый: /HEADING выдаёт имя файла перед первой его
совпавшей записью, /NOHEADING отменяет это.

Заголовок состоит из линейки звёздочек, спецификации файла и его
отметки времени, так что просмотр нескольких файлов читается как
листинг:

```
******************************************************************
src/srchmat.c                            1-AUG-2026 13:25:53.00
```

Отметка -- та же, с которой работает отбор: время последнего
изменения, а при /CREATED -- время последнего изменения индексного
дескриптора. Поэтому запуск с /SINCE показывает именно то время, с
которым он сравнивал. Спецификация, не умещающаяся в колонку,
сдвигает отметку вправо, а не обрезается.

Файл, в котором ничего не совпало, не объявляется вовсе, поэтому при
просмотре целого дерева называются только те файлы, которым есть что
сказать.

По умолчанию заголовки включены.

## /OUTPUT -- запись результата в файл

```
/OUTPUT=спецификация-файла
```

Записывает совпавшие записи в названный файл вместо стандартного
вывода. Существующий файл усекается.

Диагностика по-прежнему уходит в стандартный поток ошибок, так что в
файле оказывается только результат.

## /LOG -- сообщать о каждом просмотренном файле

Квалификатор отрицаемый. /LOG сообщает о каждом файле по его
завершении:

```
%SEARCH-I-SEARCHED, alpha.txt, 7 records searched, 1 matched
```

Кроме того, ещё до открытия первого файла сообщается, во что
превратилась команда -- строки поиска, способ их объединения, файлы
и то, что их сужает, -- а также абсолютное время, в которое
развернулось значение /SINCE или /BEFORE:

```
%SEARCH-I-SELTIME, /SINCE=TODAY is 21-AUG-2026 00:00:00.00
%SEARCH-I-SEARCHING, for "alpha", "beta" combined by AND, the case is ignored
%SEARCH-I-SELECTING, in *.c, /RECURSIVE, /EXCLUDE=(build/%*)
```

На это стоит взглянуть, когда запуск ничего не нашёл: команда несёт
кавычки, шаблоны и умолчания, и отсюда видно, пережили ли кавычки
командный интерпретатор и те ли умолчания подразумевались.

Сообщение уходит в стандартный поток ошибок. По умолчанию
протоколирование выключено.

## /STATISTICS -- итоги просмотра

Квалификатор отрицаемый. /STATISTICS выдаёт в конце работы число
просмотренных файлов и записей, число прочитанных символов, число
совпавших записей, число выданных строк и затраченное время.

Итоги идут туда же, куда и записи, поэтому /OUTPUT захватывает и их.

## /EXCLUDE -- исключение файлов

```
/EXCLUDE=(шаблон[,...])
```

Отбрасывает файлы, имя которых подходит под шаблон. Шаблоны -- те же,
что и в спецификации файла.

Шаблон, содержащий косую черту, сопоставляется с полной спецификацией
файла, не содержащий -- только с его именем:

```
/EXCLUDE=*.o            все объектные файлы дерева
/EXCLUDE=build/%*       один каталог из него
```

В исключённый каталог утилита не спускается вовсе -- именно поэтому
/EXCLUDE обходится дёшево на большом дереве.

## /SINCE -- файлы не старше заданного времени

```
/SINCE=время
```

Просматривает только файлы, отметка времени которых не старше
заданной. О записи времени см. тему ВРЕМЯ, о выборе отметки --
/MODIFIED.

По дельте -- 0-1:00 -- и по ключевому слову -- TODAY -- не видно, на
какую дату они пришлись, поэтому /LOG сообщает результат разбора:

```
%SEARCH-I-SELTIME, /SINCE=0-1:00 is  1-AUG-2026 13:52:20.00
```

## /BEFORE -- файлы старше заданного времени

```
/BEFORE=время
```

Просматривает только файлы, отметка времени которых старше заданной.
Вместе с /SINCE задаёт интервал.

Полученное время сообщается под /LOG так же, как и для /SINCE.

## /MODIFIED -- отбор по времени изменения

Указывает, что /SINCE и /BEFORE применяются ко времени последнего
изменения файла. Это поведение по умолчанию.

/MODIFIED и /CREATED нельзя задавать вместе; попытка отвергается с
%SEARCH-E-CONFQUAL.

## /CREATED -- отбор по времени создания

Указывает, что /SINCE и /BEFORE применяются ко времени создания
файла.

Linux не хранит времени создания, на которое мог бы опереться
переносимый код, поэтому квалификатор обслуживается временем
последнего изменения индексного дескриптора -- ближайшим, что есть в
системе. Эта отметка сдвигается и при смене прав или владельца, не
только при изменении содержимого.

## /RECURSIVE -- спуск в подкаталоги

Квалификатор отрицаемый. /RECURSIVE обходит всё дерево под каждым
каталогом спецификации, что соответствует [...] в спецификации
каталога OpenVMS:

```
$ search '*.c' STS$K_ /RECURSIVE
```

Шаблон применяется к имени файла на каждом уровне дерева.
Символическая ссылка никогда не раскрывается -- ни на файл, ни на
каталог: ссылка на вышестоящий каталог иначе сделала бы обход
бесконечным.

Вложенность глубже 32 уровней не обходится и отмечается сообщением
%SEARCH-W-TOODEEP.

## /BINARY -- что делать с двоичным файлом

```
/BINARY=NOTE     сообщить одной строкой, что в файле есть совпадение (по умолчанию)
/BINARY=SKIP     не просматривать файл вовсе
/BINARY=TEXT     просматривать и выдавать как любой другой файл
```

Файл считается двоичным, если среди его первых 32 КБ есть байт NUL --
та же проверка, что у GREP. Его "записи" -- это то, что случайно
оказалось между двумя переводами строки, и на терминале они дают
мусор, а то и хуже. Поэтому по умолчанию файл просматривается до
первого совпадения, и вместо записей выдаётся одна строка:

```
%SEARCH-I-BINMATCH, binary file build/app.o matches
```

В статусе завершения такой файл считается совпадением.

## /FORMAT -- вид выдачи

```
/FORMAT=VMS      заголовки и записи, для человека (по умолчанию)
/FORMAT=GREP     спецификация:номер:запись, строка на запись, для программ
```

GREP выводит каждую запись отдельной строкой, перед которой стоят
спецификация файла и номер записи, -- в том виде, в каком пишет
GREP -n, чтобы её мог прочесть редактор или скрипт:

```
$ search '*.c' rte_mbuf /RECURSIVE /FORMAT=GREP
src/rx.c:118:    struct rte_mbuf *m = NULL;
```

Заголовки не выводятся, записи нумеруются независимо от /NUMBERS.
Запись окна /WINDOW отделяется от номера дефисом вместо двоеточия,
две группы записей -- строкой "--", а двоичный файл сообщается
строкой "Binary file спецификация matches".

## /THREADS -- просмотр нескольких файлов сразу

```
/THREADS=n       одновременно просматриваются n файлов, от 1 до 64
```

Файлы, выбранные обходом, просматриваются пулом потоков и выдаются
целиком, каждый в свою очередь, в том порядке, в каком их выбрал
обход: выдача, номера записей и итоги /STATISTICS те же, что у
одного потока, байт в байт. Без квалификатора потоков берётся
столько, сколько процессоров, но не больше 16.

Один большой файл -- от 32 МБ -- режется на куски по концам записей,
куски просматриваются несколькими потоками сразу и выдаются по
порядку; если записи нумеруются, сначала считаются записи каждого
куска. Так делается при /MATCH=OR и AND без /WINDOW и не для
двоичного файла; потоков на все одновременно разрезанные файлы
никогда не больше /THREADS.

/THREADS=1 просматривает все файлы в главном потоке, один за другим;
так же работает запуск с /LOG, который сообщает о каждом файле в
порядке обхода по мере просмотра, и с /PAGE, чьему листанию нужно
видеть записи по мере их появления. Диагностика по файлу -- не
открылся, слишком длинная запись -- выдаётся, когда случилась, так
что две диагностики могут прийти не в порядке обхода.

## /HELP -- выдача описания

Выдаёт описание утилиты -- эту самую библиотеку -- и завершает
работу. Следующие за квалификатором слова называют тему внутри неё:

```
$ search /HELP                  утилита целиком
$ search /HELP window           один квалификатор
$ search /HELP -- /WINDOW       то же самое, названное точно
$ search /HELP шаблоны          одна из описательных тем
```

Подтема этой библиотеки -- квалификатор, а квалификатор пишется с
косой чертой, которую командная строка самой утилиты поглощает.
Поэтому слово, не назвавшее подтемы, пробуется ещё раз с косой
чертой впереди, и две средние формы выше означают одно и то же.

Тема выдаётся так же, как её выдаёт браузер HELP, включая пейджер
/PAGE: на терминале -- по страницам, если только не задан /NOPAGE.

Библиотека ищется там, куда указывает SEARCH$HELPLIB, затем рядом с
образом -- благодаря чему установленное дерево можно переносить, --
затем там, куда продукт был настроен её устанавливать. Если не
нашлась ни одна, а также в сборке, сделанной без продукта HELP,
/HELP выдаёт встроенную в образ сводку квалификаторов, так что
сказать ему есть что всегда.

## ШАБЛОНЫ -- раскрытие спецификации файла

Спецификацию файла раскрывает сама утилита, а не интерпретатор:

```
*       любая последовательность символов, в том числе пустая
%       ровно один символ
?       ровно один символ (написание интерпретатора)
```

Шаблоны применяются к имени внутри каталога: часть спецификации до
последней косой черты -- это каталог, и она не раскрывается. Дерево
обходится квалификатором /RECURSIVE:

```
$ search 'src/*.c' alpha            один каталог
$ search '*.c' alpha /RECURSIVE     дерево от текущего каталога
```

Кавычки существенны. Незакавыченный шаблон раскроет интерпретатор
ещё до того, как утилита его увидит; обычно это срабатывает, но
обесценивает /EXCLUDE и /RECURSIVE, а шаблон, которому ничего не
соответствует, превращает в диагностику интерпретатора вместо
%SEARCH-W-NOFILES.

Внутри каталога имена читаются в порядке сравнения байтов, поэтому
два одинаковых запуска выдают файлы в одном и том же порядке.

## ВРЕМЯ -- запись значения времени

Значение /SINCE и /BEFORE читается так же, как его читает
UTIL$BINTIM модуля STARLET, плюс четыре ключевых слова:

```
1-AUG-2026              абсолютная дата, полночь
1-AUG-2026 14:30:00     абсолютные дата и время
14:30                   сегодня в половине третьего
0-1:00                  дельта: час назад от текущего момента
2-0:00                  дельта: двое суток назад
TODAY                   полночь сегодняшнего дня
YESTERDAY               полночь вчерашнего дня
TOMORROW                полночь завтрашнего дня
NOW                     текущий момент
```

Ключевое слово допускает однозначное сокращение.

Дельта -- это число суток, дефис или пробел и время суток; она
отсчитывается назад от текущего момента, так что /SINCE=0-1:00
означает "изменён за последний час".

## ЗАПИСИ -- что считается записью

Запись -- это строка. Последняя строка файла, не завершённая
разделителем строк, всё равно является записью.

Запись просматривается и выдаётся целиком, какой бы длинной она ни
была: большой файл отображается в память как есть, а маленький
читается через буфер, который растёт под длинную запись. Усекается
только запись длиннее 64 МБ в файле, который нельзя отобразить, --
канале, устройстве. Усечение сказывается и на выдаче, и на поиске --
строка за пределом не будет найдена, -- поэтому оно объявляется
сообщением %SEARCH-W-LONGREC, один раз на файл.

Номер записи указывается там, где записи считались, а считаются они
только тогда, когда номер кто-то покажет: /NUMBERS, /LOG или
/STATISTICS. Обычный запуск не считает их вовсе -- и тем быстрее, --
и сообщение тогда называет только файл и предел.

Файл, не являющийся обычным, никогда не подбирается по шаблону;
названный явно, он читается как любой другой.

## ПРИМЕРЫ

```
$ search '*.txt' error
```

Все записи всех файлов .TXT текущего каталога, содержащие строку,
без учёта регистра.

```
$ search '*.c' alpha,beta /MATCH=AND /NUMBERS
```

Записи, содержащие обе строки, с номерами строк.

```
$ search '*' STS$K_ /RECURSIVE /EXCLUDE=(build/%*,*.o)
```

Всё дерево от текущего каталога, за вычетом одного каталога и всех
объектных файлов.

```
$ search 'src/*.c' TODO "/WINDOW=(1,2)" /OUTPUT=todo.lis
```

Каждое совпадение с одной записью перед ним и двумя после, с записью
результата в файл.

```
$ search '*.log' error /SINCE=0-1:00 /LOG
```

Только журналы, изменённые за последний час, с сообщением о каждом
по завершении.

```
$ search '*.c' alpha /RECURSIVE /PAGE /HIGHLIGHT=REVERSE
```

Всё дерево, по странице за раз, с выделением каждого вхождения
строки инверсией.

```
$ search -- notes.txt /EXACT
```

Строка /EXACT внутри файла, а не квалификатор утилиты.

## СООБЩЕНИЯ -- условия, о которых сообщает утилита

```
%SEARCH-W-NOMATCHES     не совпало вообще ничего
%SEARCH-W-NOFILES       спецификация не отобрала ни одного файла
%SEARCH-E-NOSTRING      не задана строка поиска
%SEARCH-E-OPENIN        файл не открывается
%SEARCH-F-OPENOUT       не создаётся файл /OUTPUT
%SEARCH-E-READERR       файл не читается
%SEARCH-E-OPENDIR       не читается каталог
%SEARCH-F-NOMEM         не выделяется память
%SEARCH-E-IVQUAL        недопустимое значение квалификатора
%SEARCH-E-IVTIME        неверно записано значение /SINCE или /BEFORE
%SEARCH-E-CONFQUAL      два квалификатора исключают друг друга
%SEARCH-I-SEARCHED      сообщение /LOG
%SEARCH-I-SELTIME       во что развернулись /SINCE или /BEFORE
%SEARCH-I-SEARCHING     что и как ищется
%SEARCH-I-SELECTING     где ищется
%SEARCH-W-LONGREC       запись усечена
%SEARCH-W-TOODEEP       каталог вложен слишком глубоко для обхода
%SEARCH-W-TOOMANY       список длиннее, чем принимает утилита
%SEARCH-E-NOTOPIC       /HELP называет тему, которой нет в библиотеке
%SEARCH-I-BINMATCH      в двоичном файле есть совпадение (вывод, /BINARY=NOTE)
```

Диагностику выдаёт подсистема сообщений библиотеки STARLET в
стандартный поток ошибок. Она содержит дату, время и поток, в
котором возникла, а затем само условие в формате OpenVMS:

```
14-08-2026 12:25:29.279    841 %SEARCH-W-NOFILES, no file matches *.lis
```

Сборка для отладки называет ещё модуль, подпрограмму и строку --
[SEARCH\main:1039], -- что интересно тому, кто разбирается в
утилите, а не пользуется ею.
